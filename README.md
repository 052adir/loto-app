# לוטו — בדיקה על הנייר

גרסה: **1.1.0**

האתר: https://loto-app-ibmv.onrender.com/

קיצור דרך לאתר: `Lotto Online.url`.

שני טורים נשמרים פעם אחת לכל הגרלה: בחירה סטטיסטית וטור אקראי שונה.
לצדם נשמרים שני טורים אקראיים להשוואה באותה עלות. חלופת ההשוואה אינה
המלצה לרכישת טורים נוספים. אין רכישת טפסים או הבטחה ליתרון חיזוי.

## הפעלה מקומית

נדרש Node.js 22 ומעלה. אין תלויות חיצוניות.

```text
npm run update
npm start
```

הדף זמין ב־http://localhost:3000. `npm run analyze` מציג את אותה המלצה
שנשמרה בדף; רענון והפעלה מחדש אינם מגרילים טורים חדשים לאותה הגרלה.
`npm test` מריץ את בדיקות התקינות, השמירה, חישוב הזכיות וה־API.

## מקור הנתונים ובדיקות

- תוצאות: https://www.pais.co.il/Lotto/lotto_resultsDownload.aspx
- מועד וסגירת המכירה: https://www.pais.co.il/lotto/
- סכומי הפרסים: עמוד ההגרלה הפרטני של מפעל הפיס, שנבדק מול מספרי ה־CSV.
- הניתוח מוגבל להגרלות מ־04.08.2019 ואילך, בתקופת הפורמט 6 מתוך 37 וחזק
  מתוך 7 ובעלות 3 ₪ לטור רגיל. היסטוריה מתקופות אחרות אינה מעורבבת בניתוח.
- `public/draws.json` הוא כעת אובייקט עם `draws`, מקור, זמן הורדה, מועד
  ההגרלה הבאה וחתימת הקלט. כל נתוני המערכת נצרכים דרך `official-data.js`.
- העדכון נכשל אם יש כפילות במספרים, מספר מחוץ לטווח, תאריך פסול, הגרלות
  חסרות או תגובה לא תקינה. כשל בהורדה אינו מחליף את המאגר הקיים בקובץ ריק.
- בקשת ניתוח מרעננת מהמקור אם עברו יותר משעה מהעדכון. אם אין מועד רשמי
  פתוח ומאומת לא נוצרת המלצה, ואין ניחוש לפי ימי השבוע.

## שמירת המעקב

ברירת המחדל המקומית היא `.lotto-data/`, שאינה נכללת ב־Git:

- `recommendations/`: המלצות מקוריות, טורי השוואה, תאריך יצירה, מועד סגירה,
  הגרלת יעד, גרסת האלגוריתם וחתימות. יצירה אטומית ללא החלפת רשומה קיימת.
- `inputs/`: צילום הנתונים ששימש כל המלצה.
- `algorithms/`: צילום קוד הבחירה.
- `prizes/`: עמודי הפרסים שנבדקו מול תוצאות ההגרלה.

יש לגבות את התיקייה כולה. בדיקת החתימה מזהה שיבוש בקובץ, אך אינה מהווה
אישור זמן חיצוני או חסינות בפני מי שיכול לשנות גם את הקובץ וגם את החתימה.
הרשומות הן המלצות שנשמרו לבדיקה, ולא אישורי מסירה או רכישת כרטיסים.

## שרת ואתר פעיל

באתר הקיים ב־Render מופעלת ברירת מחדל של תצוגת צילום שמור. המחשב המקומי
הוא הכותב היחיד ביומן. העדכון מייצר גם published-state.json, הכולל עותק
של ההמלצות והתוצאות, ונשמר ב־Git יחד עם נתוני ההגרלות. כך הפעלה מחדש
של Render אינה מוחקת את המעקב ואינה מגרילה טורים אחרים.

האתר אינו מייצר המלצות חדשות בעצמו במצב זה. המלצה שפג מועד סגירת המכירה
שלה אינה מוצגת כפתוחה. הדף מציג את זמן העדכון ומבהיר שהעדכון תלוי במחשב.
תזמון עדכון הלוטו הקיים במחשב מפעיל את auto_deploy.bat; התוכנה אינה מוסיפה
משימה או משנה את זמני התזמון הקיימים. הגרלות שלא נשמרה להן המלצה מראש
לא נכללות בדיעבד בבדיקת הביצועים.

לבחינת אותו מצב מקומית ניתן להגדיר LOTTO_READONLY_SNAPSHOT=1 לפני ההפעלה.
אם בעתיד מחברים דיסק קבוע לשרת, אפשר להגדיר LOTTO_STATE_DIR ולהעביר אליו
את היומן. במצב כזה יש להפעיל כותב יחיד ומשותף לכל הדרכים ליצירת המלצות.
אין להתייחס לקובץ זמני בשרת כאחסון קבוע. גם כעת יש לגבות את .lotto-data
המקומית, המכילה בנוסף את צילומי הקלט וקוד האלגוריתם.

## משמעות התוצאות

המעקב מתחיל רק ברשומות שנשמרו לפני ההגרלה. שינוי תאריך ההגרלה מסומן לבדיקה
ידנית. אין שימוש בתחזית שחושבה בדיעבד כאילו נמסרה בזמן אמת.
הכסף מוצג כעלות מדומה, סכום הפרסים שפורסמו ויתרה לפני מס. פרס חסר נשאר
לא ידוע ולא הופך לאפס. פרס שפורסם כאפס עקב היעדר זוכים נשאר לא ידוע
בתרחיש המדומה. סכומי הזכייה מבוססים על הפרס שפורסם לטור; אינם חישוב מחדש
של חלוקת קופת הפרסים בהוספת זוכים מדומים ואינם כוללים מס.
הירידה המרבית מחושבת מתוך היתרה המצטברת החל מאפס, על הגרלות שנבדקו בלבד.
אין להכריז על יתרון מתוך פער קצר־טווח לעומת חלופת האקראי.

פונקציות המחקר ההיסטורי הישנות שנותרו ב־`analyze.js` אינן מחוברות לדוח
המעקב או לעדכון משקולות אוטומטי; הן אינן ראיה לביצועים שנמדדו בזמן אמת.

## הודעות

`node notify.js --dry-run` בודק הכנת הודעה בלי לשלוח. הסקריפט המקורי
`node notify.js` ממשיך להשתמש בטלגרם כשהוא מופעל במפורש או בתזמון קיים;
הוא משתמש באותה המלצה שמורה ונעצר אם עדכון המקור נכשל. דרושים משתני
`TELEGRAM_TOKEN` ו־`TELEGRAM_CHAT_ID`. אין כפתור WhatsApp שמפנה לנתיב חסר.
